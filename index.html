    About the tool

    What is PixelShrink?

    PixelShrink is a free, local-first image compressor for JPEG, PNG, WebP and GIF files. It runs in your browser, keeps your images on your device, and does not require an account, upload, or file limit.

    Most online compressors send your image to a server to process it. PixelShrink uses the browser's File API and Canvas instead. The file is decoded, resized if you ask, and re-encoded in the tab. Nothing is uploaded, and there is no analytics or advertising code on the page.

    Compression results depend on the image, dimensions, format, and quality. A photograph usually gets smaller as JPEG or WebP; a screenshot may stay smaller as PNG; a file that is already optimized can grow when re-encoded. PixelShrink compares the result with the original and keeps the original when no resize or format change was requested and the result would be larger.

    Read the image compression guide for a practical explanation of formats, quality, resizing, and privacy.

    • Input: JPEG, PNG, WebP and GIF files.
    • Output: JPEG, PNG or WebP; GIF becomes a still PNG by default.
    • Privacy: no uploads, accounts, analytics, ads, or third-party scripts.
    • Limits: no artificial file-count or file-size limits; browser memory and canvas limits apply.
    • Offline: works after the first load via a service worker.
    • Source: MIT licensed and available on GitHub.

    Frequently asked questions

    Are my images uploaded?

    No. PixelShrink reads files with the browser's File API, draws them to a local canvas, and saves the result in memory. There is no upload endpoint, no account, and no third-party script. The page's Content Security Policy also blocks outbound connections.

    Is there a file limit?

    No file-count limit and no artificial file-size limit. The only constraints are your device's memory and the browser's canvas limits. Very large images are scaled down automatically when a canvas would be too big; the result's dimensions are shown in the queue.

    What happens to GIFs and transparent images?

    GIF input uses the first frame and is saved as PNG by default. Transparency is preserved for PNG, WebP, and GIF input. If you choose JPEG, transparent areas are filled with white because JPEG does not support transparency.

    What if the compressed file is larger?

    PixelShrink compares the encoded result with the original. If no resize or format change was requested and the result would be larger, it keeps the original bytes instead of making the file worse. That row is marked “original kept”.

    Does compressing an image reduce quality?

    Lossy formats such as JPEG and WebP can discard detail as the quality setting drops. PNG output is lossless, so the quality slider does not apply. Compare the result at its intended display size before deleting the original; the guide explains the trade-offs.

    Which format should I choose?

    Use JPEG for photographs when transparency is not needed, PNG for screenshots or graphics that need lossless output, and WebP when you want a smaller modern file with optional transparency. GIF input becomes a still PNG. The format guide above and the full guide explain the details.

    Does it work offline?

    Yes, after the first visit. A service worker caches the app itself, so compression can run without a network. The service worker only stores this site's files; it never caches or transmits your images.

    Do I need an account or an install?

    No. PixelShrink runs in a modern browser with no account, sign-up, or installation. It works on desktop and mobile, and you can add images with drag and drop, the file picker, or paste.

    Is it really free?

    Yes. No ads, no accounts, no tracking, and no paid tier. The code is MIT licensed and the source is on GitHub. If you find a bug, open an issue.
